# Домашняя работа №1

Развёртывание демонстрационного стенда средствами Yandex Cloud CLI.

## Состав стенда

Стенд включает:

- собственную виртуальную сеть;
- две подсети в зонах `ru-central1-d` и `ru-central1-a`;
- два веб-сервера;
- один сервер приложения без публичного IP-адреса;
- NAT-шлюз и таблицу маршрутизации;
- целевую группу;
- сетевой балансировщик.

Префикс ресурсов: `gubaydullin-09`.

Имя окружения: `lab`.

Веб-сервис работает на порту `8027`. Балансировщик принимает HTTP-запросы на порту `80`.

## Требования

Для запуска необходимы:

- Yandex Cloud CLI (`yc`);
- `bash`;
- `jq`;
- `envsubst`;
- `curl`;
- SSH-ключ `~/.ssh/id_ed25519.pub`.

Перед запуском `yc` должен быть настроен на нужный каталог Yandex Cloud.

## Создание стенда

```bash
bash hw-01/create.sh --web-count 2
```

Количество веб-серверов можно изменить:

```bash
bash hw-01/create.sh --web-count 4
```

Также значение можно задать переменной окружения:

```bash
WEB_COUNT=4 bash hw-01/create.sh
```

Приоритет параметров:

1. аргумент `--web-count`;
2. переменная окружения `WEB_COUNT`;
3. значение по умолчанию — `2`.

Повторный запуск `create.sh` не создаёт дублирующие ресурсы.

## Проверка стенда

```bash
bash hw-01/check.sh
echo $?
```

Сценарий проверяет:

1. ответ балансировщика с HTTP-кодом 200;
2. получение ответов более чем от одного веб-сервера;
3. доступность сервера приложения с веб-сервера по внутреннему адресу.

Код возврата:

- `0` — все проверки прошли;
- `1` — хотя бы одна проверка не прошла.

## Удаление стенда

```bash
bash hw-01/destroy.sh
```

Сценарий удаляет ресурсы стенда с префиксом `gubaydullin-09`.

## Если check.sh возвращает ошибку

Если балансировщик не отвечает, следует проверить состояние виртуальных машин и целевой группы.

Если отвечает только один веб-сервер, следует проверить состояние nginx и health check целевой группы.

Если сервер приложения недоступен, следует проверить его внутренний IP-адрес, работу nginx и наличие маршрута через NAT-шлюз.
